# SMTC Player 1.1 — режим трея

Дизайн от 15.08.2026. Добавляет к существующему виджету Rainmeter второй облик:
иконка в трее и полноценное мини-окно плеера со стеклянным оформлением.

## Зачем

Виджет на рабочем столе бесполезен ровно тогда, когда музыка играет: рабочий стол
закрыт браузером или игрой. Трей виден всегда. Цель — доступ к треку и кнопкам,
не сворачивая окон.

**Не цель:** заменить виджет. Оба облика работают одновременно от одного процесса.

## Что даёт SMTC, а что нет

Замерено на живой сессии Яндекс Музыки (`ru.yandex.desktop.music`):

| Есть | Нет |
|------|-----|
| play / pause / next / prev / stop | shuffle, repeat (`IsShuffleEnabled=False`) |
| **перемотка по позиции** (`IsPlaybackPositionEnabled=True`) | скорость, rewind / fastForward |
| название, исполнитель, обложка | альбом, номер трека, жанр — приходят пустыми |

Из этого следует главное ограничение продукта: **очереди, плейлиста и лайка не будет
никогда** — SMTC их не отдаёт. Трей-версия это пульт, а не замена Яндекс Музыке.
Кнопки shuffle/repeat не рисуем: у Яндекса они мертвы. Всё, что богаче пульта,
добирается мимо SMTC — громкость, хоткеи, история.

## Архитектура

Один процесс, два потребителя одних и тех же данных:

```
smtc_bridge.exe  (мьютекс Local\RainmeterSMTCBridge, одна копия)
 ├── ядро: чтение SMTC, доводка позиции, обложка, выбор сессии   ← уже есть
 ├── выход 1: !SetVariable через WM_COPYDATA → Rainmeter          ← уже есть
 └── выход 2: NotifyIcon + WPF-окно плеера                        ← новое
```

Rainmeter-выход включается сам, если Rainmeter найден; при его отсутствии процесс
работает как самостоятельный трей-плеер. Значит один и тот же exe годится и для
`.rmskin`, и для отдельной поставки без Rainmeter.

Ядро SMTC не переписывается — к нему добавляется событие «состояние изменилось», на
которое подписаны оба выхода.

### Модули

| Модуль | Ответственность | Зависит от |
|--------|-----------------|-----------|
| `SmtcCore` | сессия, метаданные, позиция, обложка, команды | WinRT |
| `RainmeterSink` | WM_COPYDATA, `cmd.inc`, файлы обложек | `SmtcCore` |
| `TrayIcon` | иконка, кольцо прогресса, тултип, меню, колесо | `SmtcCore` |
| `PlayerWindow` | окно, стекло, две раскладки, анимации | `SmtcCore`, `AppVolume` |
| `AppVolume` | громкость процесса-источника | Core Audio |
| `Hotkeys` | глобальные сочетания | user32 |
| `History` | журнал прослушанного | — |
| `Config` | `%APPDATA%\SMTC Player\config.ini` | — |

## Оформление

Шрифты и палитра — от виджета: Aquatico + Quicksand, белое на тёмном.

### Стекло

Проверено экспериментально, оба факта важны:

- `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` **не работает** — возвращает
  `hr=0`, а размытия нет: WPF заливает клиентскую область, системная подложка под
  неё не пробивается. Наличие рамки окна не помогает.
- `SetWindowCompositionAttribute` с `ACCENT_ENABLE_ACRYLICBLURBEHIND` (state=4)
  **работает** на borderless-окне: фон за окном реально размывается.

Скругление углов — системное, `DWMWA_WINDOW_CORNER_PREFERENCE=2`.

`AllowsTransparency=true` **не используется**: он переводит WPF в программный
рендеринг, а там пиксельные шейдеры не рисуются вовсе
(`IsPixelShaderVersionSupportedInSoftware(3,0)=False`). Прозрачность берётся от DWM,
а не от WPF.

### Liquid glass

Эффект собирается из четырёх слоёв, снизу вверх:

1. **Размытие фона** — accent-акрил выше.
2. **Тинт** — `GradientColor` акцент-политики берётся из **доминирующего цвета
   обложки** с alpha ≈ `0x40`. Стекло меняет оттенок вместе с треком.
3. **Искажение** — HLSL `ps_3_0`, displacement по шумовой текстуре, применяется
   **только к слою размытой обложки**. Не ко всему окну: под шейдером текст плывёт
   и становится нечитаемым — проверено.
4. **Фаска** — `Border` с градиентной обводкой (белый 60% сверху → 15% снизу) плюс
   внешняя `DropShadowEffect`.

Анимации — `BackEase` с амплитудой вместо CSS `cubic-bezier(.175,.885,.32,2.2)`:
WPF `KeySpline` перелёт за единицу не умеет, `BackEase` умеет.

Шейдер компилируется `fxc.exe` в `.ps` и **коммитится собранным**. Это сохраняет
главное свойство проекта: `build.ps1` остаётся одной командой, Windows SDK нужен
только тому, кто правит сам шейдер.

Запасной вариант, если accent-API отвалится в будущей Windows: сплошной тёмный фон
`#E6141418`, остальные слои без изменений. Проверяется по возвращаемому коду.

### Две раскладки

Один набор компонентов, две компоновки. Переключение — кнопкой в углу окна и
пунктом меню трея, выбор запоминается в конфиге.

**Горизонтальная, 440×150** (по умолчанию): обложка 110×110 слева, справа название,
исполнитель, прогресс с таймингами, ряд кнопок и ползунок громкости.

**Вертикальная, 300×400**: обложка 220×220 сверху по центру, ниже текст, прогресс,
кнопки, громкость — облик виджета.

Длинное название проматывается плавно, а не режется многоточием.

## Поведение

### Иконка трея

- Лого приложения с **кольцом прогресса** по контуру — видно, сколько осталось.
- Тултип: `Исполнитель — Название`.
- ЛКМ — открыть/закрыть окно, СКМ — play/pause, **колесо — громкость**.
- ПКМ — меню: play/pause, вперёд, назад, раскладка, источник, история, автозапуск,
  скрыть иконку, выход.

Логотипа у проекта нет — рисуется скриптом `tools\make_logo.ps1` в размерах
16/20/24/32/48/256 из трёх набросков (нота в круге, звуковая волна, треугольник
play в стекле); вариант выбирается при реализации.

**Известное поведение Windows 11:** новые иконки трея по умолчанию прячутся под
шеврон. README должен явно требовать закрепить иконку: Параметры → Персонализация →
Панель задач → Значки в углу панели задач. Без этого «видно всегда» не выполняется.

### Окно

- Появляется над иконкой трея, прижимаясь к рабочей области экрана.
- Закрывается по потере фокуса и по `Esc` — как системные флайауты.
- Создаётся лениво при первом открытии, выгружается через 60 секунд после закрытия.
  Фоновый процесс без окна держит ~30 МБ, с открытым окном — около 128 МБ.
- Перемотка: клик и перетаскивание по полосе прогресса. Если сессия не поддерживает
  `IsPlaybackPositionEnabled`, полоса становится индикатором без взаимодействия.

### Громкость

Core Audio: `IAudioSessionManager2` → сессия по PID процесса-источника, сопоставление
`SourceAppUserModelId` с именем процесса. Крутится только источник, игра и браузер не
затрагиваются. Если сессия не нашлась, ползунок скрывается — системную громкость
подменять молча нельзя, это не то, чего ждёт пользователь.

### Хоткеи

`RegisterHotKey`. По умолчанию: `Ctrl+Alt+Space` — play/pause, `Ctrl+Alt+←/→` — трек,
`Ctrl+Alt+↑/↓` — громкость. Переопределяются в конфиге, отключаются целиком одной
настройкой. Если сочетание занято другой программой, регистрация молча не удаётся —
пишем это в лог и показываем в меню пометкой.

### История

`%APPDATA%\SMTC Player\history.tsv`: время, исполнитель, название, источник.
Последние 200 записей, обложки 60×60 рядом в `history\`. Трек считается
прослушанным после 30 секунд воспроизведения. Открывается отдельным окном-списком.
Переключиться на прошлый трек нельзя — SMTC не даёт, и в интерфейсе это не
предлагается.

## Конфигурация

`%APPDATA%\SMTC Player\config.ini`, UTF-8. Правило UTF-16LE относится только к
файлам, которые читает Rainmeter, — на этот конфиг оно не распространяется.

Ключи: раскладка, автозапуск, хоткеи, `PreferApp`, показывать иконку, глубина
истории, включённость эффекта стекла.

Автозапуск — `HKCU\...\CurrentVersion\Run`, по умолчанию **выключен**: лезть в
автозапуск без явного согласия нельзя.

## Ошибки

| Ситуация | Поведение |
|----------|-----------|
| Нет активной сессии SMTC | Иконка приглушена, тултип «Ничего не играет», окно показывает заглушку |
| Обложки нет | Раскладка схлопывается, тинт берётся нейтральный |
| accent-API вернул ошибку | Сплошной тёмный фон, остальное работает |
| Шейдер не загрузился | Слой обложки рисуется без искажения |
| Аудиосессия не найдена | Ползунок громкости скрыт |
| Хоткей занят | Пометка в меню, остальные регистрируются |
| Rainmeter не запущен | Rainmeter-выход молча выключен |

## Проверка

Автотестов у проекта нет и не заводим — это GUI поверх системного API. Проверка
ручная, по списку: оба режима раскладки, перемотка, громкость при играющей игре,
хоткеи из полноэкранного приложения, поведение при закрытии Яндекс Музыки,
переключение источника при двух сессиях, работа без Rainmeter, установка `.rmskin`
поверх версии 1.0.0.

Отдельно проверяется масштабирование: 100%, 125%, 150% DPI и второй монитор.
